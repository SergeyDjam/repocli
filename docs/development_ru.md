# Руководство разработчика

## Требования

- Rust (edition 2021; в CI используется 1.95+).
- Стандартные инструменты сборки; `xz` используется как внешний фильтр сжатия.
- Для проверки с urpmi: `urpmq` и зарегистрированное медиа с именем из примеров.

## Ежедневные команды

```bash
cargo fmt --all
cargo build --release
cargo test --release
cargo clippy --all-targets -- -D warnings
```

Интеграционные тесты, запускающие собранный бинарник, автоматически
пропускаются при `HOST != TARGET` (кросс-компиляция). Тест наличия бинарника
выполняется всегда.

## Правила кода

1. **Никакой кириллицы в исходниках**, включая комментарии. Чат и Markdown —
   на русском. Проверка: `grep -P '[\x{0400}-\x{04FF}]' src/**/*.rs`.
2. Clippy запускается с `-D warnings`. Точечный `#[allow(...)]` допустим только
   там, где альтернатива изменила бы совместимый API (например, функции `run()`
   с девятью аргументами, унаследованные от genhdlist2).
3. Каждое изменение проверяется реальной сборкой `cargo build --release`;
   не вставлять некомпилированный код в документацию или чат.
4. Каждое поведенческое изменение фиксируется в `CHANGELOG.md`, включая
   замеры производительности.
5. В runtime-пути запрещены вызовы `genhdlist2`, `librpm` и `rpm`. Парсеры —
   только Rust; внешний `xz` — настраиваемый фильтр.

## Добавление плагина формата RPM

1. Создайте `src/rpm/rpmN.rs`, реализующий `RpmReader`:

   ```rust
   pub struct RpmNReader;

   impl RpmReader for RpmNReader {
       fn format(&self) -> RpmFormat { RpmFormat::RpmN }
       fn read(&self, path: &Path) -> Result<RpmInfo> {
           universal::read_file(path) // или специфика версии
       }
   }
   ```

2. Добавьте вариант в `RpmFormat` в `detect.rs` и расширьте `classify()`:
   сопоставьте старшее число `RPMVERSION` с новым форматом.
3. Зарегистрируйте плагин в `RpmReaderRegistry::default()`.
4. Положите реальный пакет в `tests/fixtures/` и расширьте
   `reads_all_fixture_formats`.

Больше ни один модуль не меняется: `main.rs` диспетчеризует только через реестр.

## Работа с форматами

- `src/rpm/header.rs` — единственное место, интерпретирующее бинарный заголовок.
  Сохраняйте проверки границ; никогда не индексируйте срез по непроверенному
  смещению тега.
- `universal.rs` владеет соответствием тегов полям. При добавлении тега объявите
  именованную константу с upstream-именем RPM.
- Форматы вывода должны соответствовать эталонным источникам из
  [formats_ru.md](formats_ru.md). Не выдумывайте новые `@field@` в synthesis:
  неизвестные имена ломают urpmi.
- XML-писатель использует `quick_xml`; каждая запись файла заканчивается `\n`,
  а элемент `<info>` содержит атрибуты `sourcerpm`, `url`, `license`.

## Диагностика

| Инструмент | Назначение |
|---|---|
| `REPOCLI_TIMING=1 repocli …` | времена фаз: `metadata`, `pipeline`, `finalize`, `merge:synthesis`, `merge:hdlist`, `merge:xml` |
| `cargo run --bin rpm_diag -- <rpm>` | дамп lead, сигнатуры и индекса заголовка |
| `cargo run --bin rpm_parse_correct -- <rpm>` | эвристический парсер (legacy) |
| `cargo run --bin compare_headers -- <rpm>` | сравнение эталонного и сырого заголовков |
| `tests/fixtures/*.rpm` | реальные пакеты rpm4/rpm5/rpm6 для регрессионных тестов |

## Профилирование

Профилируйте до оптимизации; узкие места в этом проекте были такими:

1. Сканер заголовков проходил весь RPM побайтно — исправлено остановкой после
   сигнатуры и основного заголовка (6,838 с → 0,749 с на 97 пакетах).
2. Внешний `xz -7 -T0` для synthesis и XML — заменён на `xz -1`
   (0,749 с → 0,323 с).
3. Per-header gzip с уровнем по умолчанию — уровень 1
   (0,323 с → 0,176 с).

Не возвращайте `rayon` и многопоточные компрессоры без `strace -c`: предыдущая
реализация тратила 99,7% времени в `futex`.

## Проверка с urpmi

После изменения форматов вывода:

```bash
repocli /path/to/rpms/media
urpmq -f --media <media> --list
urpmq -f --media <media> -ai <package>
```

Первая команда должна вывести все пакеты, вторая — корректные Version,
Group, Size и Summary. Это одновременно проверяет hdlist, synthesis и XML.
